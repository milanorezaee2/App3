## قدم ۴ — آماده‌سازی تنظیم ساخت (بدون ساخت واقعی) ⚠️

**نتیجهٔ صریح: APK ساخته نشد.** این محیط نمی‌تواند بسازد، نه به‌خاطر تنظیمات بلکه به‌خاطر شبکه:

| میزبان | وضعیت | برای چه لازم است |
|---|---|---|
| `archive.ubuntu.com` | ✘ مسدود | نصب JDK |
| `dl.google.com` | ✘ مسدود | Android SDK و build-tools |
| `repo1.maven.org` | ✘ مسدود | وابستگی‌های Gradle |
| `registry.npmjs.org` | ✔ باز | npm |
| `github.com` | ✔ باز | مخزن |

همچنین `java` و `gradle` و Android SDK در محیط نصب نیستند. پس عدد ۱۰۰ مگابایت هنوز **تخمینی** است و اولین اندازه‌گیری واقعی در CI خودتان انجام می‌شود.

### آنچه آماده شد و واقعاً آزمایش شد

**۱. افزونهٔ کنترل معماری — `plugins/withAndroidAbis.js`**

معماری‌های CPU را از متغیر محیطی `MILO_ANDROID_ABIS` می‌گیرد. سه حالت آزمایش شد:

```
بدون متغیر         → reactNativeArchitectures=armeabi-v7a,arm64-v8a,x86,x86_64   (بی‌تغییر ✔)
arm64-v8a,armeabi-v7a → reactNativeArchitectures=arm64-v8a,armeabi-v7a           (اعمال شد ✔)
arm64-v8a,mips     → Error: Unknown ABI(s): mips                                  (خطای روشن ✔)
```

این را با `npx expo prebuild` واقعاً اجرا و در `android/gradle.properties` تأیید کردم.

**۲. روشن‌کردن R8 و حذف منابع**

در `app.json`:

```json
["expo-build-properties", {
  "android": {
    "enableMinifyInReleaseBuilds": true,
    "enableShrinkResourcesInReleaseBuilds": true
  }
}]
```

نکتهٔ مهمی که در جریان کار پیدا شد: کلید قدیمی `enableProguardInReleaseBuilds` در این قالب Gradle به `android.enableMinifyInReleaseBuilds` نگاشت می‌شود و کد Gradle دقیقاً همین دومی را می‌خواند. با prebuild تأیید شد که هر دو کلید در `gradle.properties` تولید می‌شوند.

**۳. گزارش ترکیب APK — `scripts/apk-report.mjs`**

APK یک zip است، پس این اسکریپت فهرست مرکزی آن را مستقیم می‌خواند و حجم را بر اساس آنچه واقعاً هست دسته‌بندی می‌کند: `lib/<abi>`، `classes.dex`، `assets`، `res`.

چون APK واقعی در دسترس نبود، با زیپ ساختگی آزمایش شد:

- ساختار واقعی یک APK یونیورسال → تفکیک درست چهار معماری و نمایش سهم هر کدام
- ZIP64 با **۷۰٬۰۰۰ فایل** → فهرست کامل خوانده شد
- بودجه: `--limit-mb 3` → exit code 1 ، `--limit-mb 50` → exit code 0

**۴. اتصال به CI**

`apk-learner.yml` یک ورودی جدید گرفت:

```yaml
workflow_dispatch:
  inputs:
    abis:
      description: 'CPU architectures to package...'
      default: ''
```

و مرحلهٔ گزارش با بودجهٔ ۱۲۰ مگابایت (نرده، نه هدف — تا فقط جلوی رشد را بگیرد).
`android-build.yml` هم گزارش اطلاعاتی گرفت برای هر چهار APK.

### محدودیتی که کشف شد

تست دودی CI روی شبیه‌ساز **x86_64** اجرا می‌شود:

```yaml
api-level: 30
arch: x86_64
```

یعنی اگر APK را arm-only بسازیم، تست دودی نمی‌تواند نصبش کند. به همین دلیل محدودکردن معماری **به‌صورت پیش‌فرض روشن نشد**؛ باید آگاهانه انتخاب شود.

### ⚠️ هشدار دربارهٔ R8

R8 کد و منابع بلااستفاده را حذف می‌کند، ولی می‌تواند کدی را که فقط از طریق reflection صدا زده می‌شود هم حذف کند. ساخت موفق تضمین اجرا نیست. **قبل از انتشار، APK را روی دستگاه واقعی باز کنید.** اگر مشکلی دید، فقط این دو خط را از `app.json` بردارید.

### درس‌هایی که در مسیر یاد گرفتیم

**۱. حجم artifact در GitHub، حجم APK نیست.** فایل فشرده‌ای که GitHub برای دانلود می‌سازد، ۴۲ مگابایت بود در حالی که خود APK ۸۷.۵ مگابایت است. دلیل: کتابخانه‌های `.so` داخل APK فشرده نمی‌شوند (برای بارگذاری سریع‌تر)، پس دوباره زیپ‌کردن آن‌ها را نصف می‌کند. **هر عددی که از artifact گرفته شود گمراه‌کننده است.**

**۲. ست‌کردن `reactNativeArchitectures` در `gradle.properties` کافی نیست.** قالب تولیدشدهٔ اکسپو هیچ‌جا آن را نمی‌خواند و کتابخانه‌های از پیش ساختهٔ AARها هم معماری خودشان را می‌آورند. باید `ndk { abiFilters }` مستقیم در `defaultConfig` نوشته شود.

**۳. بررسی بودجه نباید قبل از آپلود باشد.** اجرای شکست‌خوردهٔ وسط کار، APK را ساخت ولی چون بررسی حجم قبل از آپلود بود، فایل دور ریخته شد. حالا بودجه در آخرین مرحله اعمال می‌شود.

### پوشش آزمون

- تست دودی شبیه‌ساز برای این APK **به‌صورت عمدی رد شد**، چون شبیه‌ساز x86_64 است و این APK کتابخانهٔ x86_64 ندارد. مرحله با یک پیام روشن رد می‌شود، نه با خطا.
- پوشش شبیه‌ساز از بیلد یونیورسال در workflow «Build MiloMultilang Android APK» می‌آید.
- **R8 در اجرای قبلی با چهار معماری روی شبیه‌ساز آزمون شد و پاس شد**، پس حذف کد با R8 چیزی را نشکسته است.

## نکته‌ای که باید صریح گفته شود

حجم پوشهٔ `.git` از ۷.۸ به ۸.۱ مگابایت **رسیده** و کم نشده. دلیلش این است که آن تصویر ۳.۶ مگابایتی هنوز داخل **تاریخچهٔ گیت** هست. حذف فایل از آخرین کامیت، تاریخچه را پاک نمی‌کند.

یعنی:

- **کلون تازه** هنوز همان ۳.۶ مگابایت را دانلود می‌کند.
- **فایل‌های کاری** از ۱۸ به ۹.۶ مگابایت رسیده‌اند.
- برای کوچک‌کردن `.git` باید تاریخچه بازنویسی شود (`git filter-repo` یا BFG)، که کار جداگانه‌ای است و چون مخزن فقط یک کامیت اولیه دارد، هزینهٔ کمی دارد. **پیشنهاد می‌کنم بعد از تمام‌شدن همهٔ قدم‌ها و در یک عملیات جداگانه انجام شود.**
