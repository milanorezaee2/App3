# صدای جایگزین — «دستگاه اول، ضبطشده فقط بهعنوان کمکافکن همان ۱۰٪»

## چرا این مدل؟

روی **۹۰٪ گوشیها صدای TTS خود دستگاه عالی** است؛ روی **۱۰٪ صدا بد و منقطع** است (موتور ناقص،
دادهٔ صوتی نصبنشده، صدای شبکهای، باگ سازنده). مدل اول «ضبطشده جایگزین همه شود» اشتباه بود، چون ۹۰٪
را به صدای رباتی eSpeak تنزل میداد تا ۱۰٪ درست شود.

**تصمیم نهایی:** صدای دستگاه پیشفرض و دستنخورده میماند؛ فایلهای `mp3` فقط روی همان دستگاههای
مشکلساز استفاده میشوند. هیچ توکن TTS، اکانت، پرداخت یا سرویس تحریمشده لازم نیست.

## دقیقاً چه پیادهسازی شد

| قطعه | رفتار |
|---|---|
| `lib/content/speechFallback.ts` | flag دائمی روی دستگاه (AsyncStorage/localStorage)، `noteSpeechSuccess` / `noteSpeechFailure`، **سوئیچ خودکار بعد از ۳ خطا** |
| `russianSpeech` / `turkishSpeech` / `starterSpeech` / `responsiveSpeech` | **اول موتور دستگاه**؛ ضبطشده فقط وقتی flag روشن است، یا آخرین تلاش بعد از خطای سخت. انگلیسی هم وصل شد → هر ۶ زبان یکسان |
| `app/profile.tsx` → حساب → **صدای جایگزین** | کلید دستی: «صدای گوشی · پیشفرض» ⇄ «صدای ضبطشده · روشن» |
| تشخیص خودکار | `onError` و «قطع پخش در کمتر از ۶۰۰ms» شمارش میشوند؛ بعد از ۳ بار همان دستگاه خودکار سوئیچ میکند |
| `lib/content/packAudio.ts` | پخش URL ساده **یا** برش `milo-segment:<bundle>.mp3?start=<ms>&dur=<ms>`؛ باندل یکبار دانلود و کش میشود (آفلاین بعد از بار اول) |
| `lib/content/packs.ts` | اگر باکت عمومی Supabase پیکربندی نشده باشد، بستهها از asset عمومی `packs-all.json` همان ریلیز خوانده میشوند |

**محدودیت صادقانه:** از JavaScript نمیتوان «صدا پخش میشود ولی خشخدار/منقطع است» را تشخیص داد؛
فقط خطای سخت و قطع زودهنگام قابلتشخیصاند. پس **کلید دستی، راهحل قابلاطمینان است** و سوئیچ خودکار
فقط تور ایمنی است.

## آن ۱۰٪ دقیقاً چه کار کنند؟

**هیچ چیزی نخرند، هیچ توکنی نسازند، هیچ چیزی توی چت نفرستند.** فقط روی همان دستگاه:
پروفایل ← حساب ← **«صدای جایگزین»** را روشن کنند. از آن بعد جملهها از فایل ضبطشده پخش میشود.
۹۰٪ بقیه هیچ تغییری حس نمیکنند. کلید توی نسخهٔ #116 نیست ← **یک APK تازه لازم است**.

## فایلها کجا هستند؟ (بدون هیچ Secret تازهای)

ابتدا فرض شده بود `SUPABASE_SERVICE_ROLE_KEY` از قبل توی CI هست؛ **لاگ اجرا نشان داد نیست** و باکت
`content-packs` هم ساخته نشده بود (خطای `Bucket not found`). رندر ۱۵٬۲۴۳ جمله با موفقیت انجام شد،
فقط مرحلهٔ آپلود به Supabase متوقف شد. برای همین مسیر انتشار عوض شد:

| چیز | محل | نیاز |
|---|---|---|
| ۳۴ فایل `de-A1.mp3` … `ru-C1.mp3` (دو بستهٔ خالی en/A1 و en/A2 باندل ندارند) | **GitHub Release `milo-content-v1`** | `GITHUB_TOKEN` خودکار Actions |
| `packs-all.json` + `manifest.json` | همان ریلیز | همان |
| بستههای JSON نسخهبندیشده | داخل مخزن (کامیت) | همان |
| mirror به باکت Supabase | فقط **اگر** `SUPABASE_SERVICE_ROLE_KEY` موجود باشد | اختیاری، الزامی نیست |

یعنی ۳۴ باندل + ۲ فایل JSON بهجای ۱۵٬۲۴۳ شیء (سقف ریلیز ۱۰۰۰ asset است)، بدون سرویس پولی و
بدون کلید service-role. اپ همان هاستی را استفاده میکند که APKها از آن دانلود میشوند؛ پس اگر APK میرسد،
صدا هم میرسد. URL ثابت:
`https://github.com/milanorezaee2/App3/releases/download/milo-content-v1/…`

### دستور production (همهاش داخل CI)

```
node scripts/content/renderOfflineAudio.mjs --scope all --workers 8
node scripts/content/packAudioBundles.mjs      # ۱۵٬۲۴۳ → ۳۴ باندل + offset هر جمله
node scripts/content/finalizeAudioPacks.mjs    # bump نسخهها (کش اپ باطل شود)
node scripts/content/buildContentRelease.mjs   # packs-all.json
gh release upload milo-content-v1 --clobber content-packs/audio-bundles/*.mp3 …
```

ورکفلو [`tts-offline.yml`](../.github/workflows/tts-offline.yml) همهٔ اینها را انجام میدهد؛ روی شاخهٔ
فیچر کافی است محتوای `.github/workflows/tts-trigger.txt` تغییر کند (`all espeak`).

## موتورها (هیچکدام کلید نمیخواهند)

| موتور | کیفیت | نیاز |
|---|---|---|
| **eSpeak NG** (WASM + lamejs) | رباتی ولی **پیوسته، روان و یکسان** | `npm i --no-save espeak-ng@1.0.2 lamejs@1.2.1` — تستشده، بدون اینترنت |
| **Piper** (ONNX عصبی) | طبیعیتر | `pip install piper-tts` + مدلهای عمومی (بدون توکن)؛ `engine=auto`، نبود مدل → eSpeak |
| TTS داخلی Arena | طبیعی | بدون کلید، ولی سقف ۱۰ کلیپ در نوبت؛ فقط چند جملهٔ منتخب |

نمونهٔ واقعی: `docs/audio-samples/*.mp3` — شش زبان، ساختهشده در همان sandbox بدون کلید یا تماس
شبکهای (~۱۰KB هر جمله). `renderOfflineAudio.mjs` با ۸ worker داغ، ۱۵ هزار جمله را در حدود ۴۳ دقیقه
روی runner استاندارد ساخت: **۱۵٬۲۴۳/۱۵٬۲۴۳، صفر خطا**.

## مقیاس و هزینه

- **۱۵٬۲۴۳ جمله** در ۳۶ بسته (۳۴ بستهٔ غیرخالی) · **۱۰٫۵ ساعت گفتار · ۲۱۶ MB** MP3 مونو ۴۸ kbps / ۲۲٫۰۵ kHz
- ۳۴ باندل (۰٫۹–۱۹ MB) · **۰ دلار، ۰ توکن، ۰ Secret تازه**
- فایلهای صوتی وارد Git نمیشوند (`content-packs/audio/` و `audio-bundles/` در `.gitignore`)
- `scope=pilot` = `pre+A1` (۱٬۷۰۷ کلیپ) برای تست سریع؛ `scope=all` = پوشش کامل

## مقایسهٔ سه گزینه

| گزینه | ۹۰٪ خوب | ۱۰٪ بد | هزینه |
|---|---|---|---|
| فقط TTS دستگاه (وضع #116) | عالی | بد/منقطع | ۰ |
| جایگزینی کامل با ضبطشده (مدل اول) | **تنزل به رباتی** | درست | ۰ |

ولی دیگر مسیر پیشنهادی نیست: تحریم دسترسی به توکن را مسدود میکند.

## محدودیتهای باقیمانده

- صدای eSpeak زیبا نیست؛ مزیتش **پیوسته و قابلاطمینان** بودن روی موتور خراب است.
- تا وقتی ریلیز `milo-content-v1` ساخته نشود، کلید پروفایل بیتأثیر و بیریسک است
  (`tryPlayRecorded` برمیگردد `false` و همان موتور دستگاه ادامه میدهد).
- درسهای باندلشدهٔ داخل APK (۲٬۸۷۶ جمله) فعلاً موتور دستگاهاند؛ پوشش صدای آنها ایندکس جدایی میخواهد.
- تولید صدا تلفظ را تضمین میکند، نه درستی جملات را؛ بازبینی `docs/native-review.md` پابرجاست.
- دسترسی `huggingface.co` برای مدلهای Piper از ایران تأیید نشده؛ `engine=espeak` مسیر تضمینشده است.
