# صدای جایگزین — مدل «دستگاه اول، ضبطشده فقط بهعنوان کمکافکن»

## مسئلهای که واقعاً وجود دارد

روی **۹۰٪ گوشیها صدای TTS خود دستگاه عالی** است؛ روی **۱۰٪ صدا بد و منقطع** است (موتور ناقص،
صدای شبکهای، دادهٔ صوتی نصبنشده، باگ سازنده). پس «جایگزینی کامل صدای دستگاه با فایل ضبطشده»
که ابتدا پیاده کرده بودم **تصمیم درستی نیست**: ۹۰٪ را به صدای رباتی eSpeak تنزل میداد تا ۱۰٪
درست شود.

**تصمیم نهایی:** صدای دستگاه همچنان پیشفرض و دستنخورده میماند. فایلهای `mp3` آفلاین فقط
**روی همان دستگاههای مشکلساز** استفاده میشوند. هیچ توکن، اکانت، پرداخت یا سرویس خارجی لازم نیست؛
صدا داخل runner گیتھاب با موتور متنباز ساخته میشود و به باکت Supabase موجود آپلود میشود (همان
`SUPABASE_SERVICE_ROLE_KEY`ای که الان هم بستهها را منتشر میکند).

## دقیقاً چه پیادهسازی شد

| قطعه | رفتار |
|---|---|
| `lib/content/speechFallback.ts` | flag دائمی روی دستگاه (AsyncStorage)، `noteSpeechSuccess` / `noteSpeechFailure`، و **سوئیچ خودکار بعد از ۳ خطا** |
| `russianSpeech` / `turkishSpeech` / `starterSpeech` / `responsiveSpeech` | **اول موتور دستگاه**؛ ضبطشده فقط وقتی flag روشن است، یا بهعنوان آخرین تلاش بعد از خطای موتور. مسیر انگلیسی هم وصل شد، پس هر ۶ زبان یکساناند |
| `app/profile.tsx` → حساب → **صدای جایگزین** | کلید دستی: «صدای گوشی · پیشفرض» ⇄ «صدای ضبطشده · روشن» |
| تشخیص خودکار | `onError` و «قطع شدن پخش در کمتر از ۶۰۰ms» شمارش میشوند؛ بعد از ۳ بار، همان دستگاه خودکار به ضبطشده میرود |
| `packAudio.ts` / `packs.ts` | URLها هنگام لود بستهها ثبت میشوند؛ تغییری در درسها و رابط لازم نیست |

**محدودیت صادقانه:** از JavaScript نمیتوان «صدا پخش میشود ولی خشخدار/منقطع است» را تشخیص داد؛
فقط خطای سخت و قطع زودهنگام قابل تشخیصاند. به همین دلیل **کلید دستی، راهحل قابلاطمینان است**
و سوئیچ خودکار فقط یک تور ایمنی است.

## آن ۱۰٪ دقیقاً چه کار کنند؟

**هیچ چیزی نباید بخرند یا وصل کنند.** فقط روی همان دستگاه: پروفایل ← حساب ← «صدای جایگزین» را
روشن کنند. از آن بعد جملهها از فایل ضبطشده پخش میشود (بعد از اولین همگامسازی، آفلاین هم کار
میکند). ۹۰٪ بقیه هیچ تغییری حس نمیکنند.

برای اینکه کلید اثر داشته باشد، فایلهای صوتی باید یکبار تولید شوند — آن هم **رایگان** و بدون کلید:

```
# در CI (یا همان ورکفلو، بدون هیچ Secret تازهای)
node scripts/content/renderOfflineAudio.mjs --scope all --workers 8
node scripts/content/finalizeAudioPacks.mjs
```

راهاندازی از روی شاخهٔ فیچر: محتوای `.github/workflows/tts-trigger.txt` را `all espeak` بگذارید و
push کنید (چون `workflow_dispatch` روی شاخهٔ فیچر معمولاً ثبت نمیشود). ورکفلو
[`tts-offline.yml`](../.github/workflows/tts-offline.yml) رندر ← bump نسخه ← مانیفست ← آپلود ←
کامیت JSONها را انجام میدهد. یک بیلد APK هم لازم است تا کلید پروفایل و مسیر پخش انگلیسی روی
دستگاه برسد.

## موتورها (هیچکدام کلید نمیخواهند)

| موتور | کیفیت | نیاز |
|---|---|---|
| **eSpeak NG** (WASM + lamejs) | رباتی ولی **پیوسته، روان و یکسان** | `npm i --no-save espeak-ng@1.0.2 lamejs@1.2.1` — تستشده، بدون اینترنت |
| **Piper** (ONNX عصبی) | طبیعیتر | `pip install piper-tts` + مدلهای عمومی Piper (بدون توکن)؛ `engine=auto`، در صورت نبود مدل → eSpeak |
| TTS داخلی Arena | طبیعی | بدون کلید، ولی سقف ۱۰ کلیپ در نوبت؛ فقط برای چند جملهٔ منتخب |

نمونهٔ واقعی: `docs/audio-samples/*.mp3` — شش زبان، ساختهشده در همان sandbox بدون هیچ کلید یا
تماس شبکهای (~۱۰KB هر جمله). `renderOfflineAudio.mjs` با ۸ worker داغ، ۱۵ هزار جمله را در
چند دقیقه میسازد (ماژول WASM در هر worker گرم میماند).

## مقیاس و هزینه

- **۱۵٬۲۴۳ جمله** در ۳۶ بسته · ≈ ۱۵۰–۲۰۰ MB (MP3 مونو ۴۸ kbps) · **۰ دلار**
- فایلها وارد Git نمیشوند (`content-packs/audio/` در `.gitignore`)؛ فقط در Storage میمانند
- `scope=pilot` = `pre+A1` (۱٬۷۰۷ کلیپ، ~۱۷ MB) برای تست؛ `scope=all` = پوشش کامل
- مدلهای عمومی Piper هم دانلودشان نیازی به توکن ندارد (تحریم مانع «اکانت/پرداخت» است، نه فایل عمومی)

## مقایسهٔ سه گزینه

| گزینه | ۹۰٪ خوب | ۱۰٪ بد | هزینه |
|---|---|---|---|
| فقط TTS دستگاه (وضع فعلی) | عالی | بد/منقطع | ۰ |
| جایگزینی کامل با ضبطشده (مدل اول) | **تنزل به رباتی** | درست | ۰ |
| **ترکیبی حاضر** ✅ | **دستنخورده، عالی** | **ضبطشده، پیوسته** | ۰ |

`scripts/content/ttsProvider.mjs` (OpenAI/Google/ElevenLabs) همچنان بهعنوان گزینهای اختیاری برای
تیمهایی با دسترسی به آن سرویسها باقی است، ولی دیگر مسیر پیشنهادی نیست.

## محدودیتهای باقیمانده

- صدای ضبطشدهٔ eSpeak زیبا نیست؛ مزیتش **پیوسته و قابلاطمینان** بودن روی موتور خراب است.
- تا وقتی رندر اجرا نشود، کلید پروفایل خانهای خالی را روشن میکند (`tryPlayRecorded` برمیگردد
  `false` و همان موتور دستگاه ادامه میدهد) — یعنی بیتأثیر و بیریسک است.
- درسهای باندلشدهٔ داخل APK (۲٬۸۷۶ جمله) فعلاً موتور دستگاهاند؛ پوشش آنها نیازمند ایندکس
  صدای جداست.
- تولید صدا تلفظ را تضمین میکند، نه درستی جملات را؛ بازبینی `docs/native-review.md` پابرجاست.
