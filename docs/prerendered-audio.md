# قدم آخر — صدای ازپیشتولیدشده، **بدون هیچ توکنی**

## پاسخ کوتاه (محدودیت تحریم)

نیازی به توکن، اکانت، پرداخت یا سرویس خارجی نیست. صدا **داخل همان runner گیتھاب** و بهصورت کاملاً
آفلاین ساخته میشود و فایلهای `mp3` مستقیم به باکت عمومی Supabase آپلود میشوند. تحریم مانع
«گرفتن API key» است، نه اجرای یک موتور متنباز روی CI. تنها Secretای که استفاده میشود
`SUPABASE_SERVICE_ROLE_KEY` است که **همین الان هم** در ریپو هست و بستهها را منتشر میکند — هیچ
کلید تازهای لازم نیست.

## اگر صدا اضافه شود، چه تغییری میکند؟

امروز هر جمله با موتور TTS خود گوشی خوانده میشود (صدای متفاوت روی هر دستگاه، گاهی لهجهٔ غلط،
وابسته به نصب موتور زبان). با فایلهای ضبطشده: صدای ثابت و یکسان روی همهٔ گوشیها، **آفلاین** بعد از
اولین همگامسازی، و در صورت نبود فایل همان رفتار قدیمی بدون افت. `tryPlayRecorded` قبل از موتور
دستگاه اجرا میشود و نرخ پخش آهسته/طبیعی حفظ میشود. تغییری در درسها یا رابط لازم نیست؛ فقط فیلد
`audio` هر جمله پر میشود. مسیر پخش **انگلیسی** هم در این مرحله وصل شد، پس هر ۶ زبان یکساناند.

## موتورها (هیچکدام کلید نمیخواهند)

| موتور | کیفیت | نیاز | وضعیت |
|---|---|---|---|
| **eSpeak NG** (WASM) | رباتی ولی روان، قابلفهم، یکسان | `npm i --no-save espeak-ng@1.0.2 lamejs@1.2.1` | ✅ همینجا تست شد، ۶ زبان، بدون اینترنت |
| **Piper** (ONNX عصبی) | طبیعیتر، نزدیک گویندهٔ بومی | `pip install piper-tts` + مدلهای **عمومی** Piper (بدون توکن) | اختیاری؛ اگر مدل در دسترس نباشد خودکار به eSpeak برمیگردد |
| TTS داخلی Arena | طبیعی | بدون کلید | فقط برای چند جملهٔ منتخب (سقف ۱۰ کلیپ در نوبت)، مقیاسپذیر نیست |

`scripts/content/offlineTts.mjs` هردو موتور را پشتیبانی میکند: `TTS_ENGINE=espeak` یا
`PIPER_MODEL_DE=/path/de.onnx` (و به همین ترتیب برای ۵ زبان دیگر). خروجی WAV با `lamejs` به MP3
تبدیل میشود، پس حتی `ffmpeg` هم لازم نیست.

**نمونهٔ واقعی:** `docs/audio-samples/*.mp3` — شش فایل برای شش زبان، ساختهشده در همان sandbox بدون
هیچ کلید یا تماس شبکهای. ~۸–۱۲ کیلوبایت برای هر جمله.

## زیرساخت آماده

| قطعه | وضعیت |
|---|---|
| `scripts/content/renderAudio.mjs` | یک کلیپ بهازای هر جمله، نوشتن URL در پک |
| `scripts/content/offlineTts.mjs` | موتور آفلاین، تستشده |
| `scripts/content/finalizeAudioPacks.mjs` | bump نسخه (اپ با نسخهٔ unchanged پس نمیدهد) + مانیفست |
| `.github/workflows/tts-offline.yml` | `workflow_dispatch`: `scope=pilot\|all`، `engine=espeak\|auto`؛ رندر + آپلود + کامیت JSONها |
| `lib/content/packAudio.ts` / `packs.ts` / ۴ مسیر پخش | آماده |
| CI بیلد APK | همین حالا `*.mp3` را با `Content-Type: audio/mpeg` آپلود میکند |
| `.gitignore` | `content-packs/audio/` — باینریها وارد Git نمیشوند، فقط در Supabase میمانند |

راهاندازی (بدون دادن هیچ کلیدی در چت):

```
gh workflow run tts-offline.yml -f scope=pilot -f engine=espeak
```

## مقیاس واقعی

- **۱۵٬۲۴۳ جمله** در ۳۶ بستهٔ منتشرشده · ۵۵۲٬۰۳۳ نویسه ≈ ۱۰ ساعت گفتار
- حجم: ~۱۵۰–۲۰۰ MB (MP3 مونو ۴۸ kbps، ۲۲٫۰۵ kHz) · فایلها وارد Git نمیشوند
- `pilot` = `pre + A1` = ۱٬۷۰۷ کلیپ (~۱۷ MB) برای شروع؛ `all` = بقیه
- هزینهٔ سرویس: **صفر دلار**. فقط دقایق runner گیتھاب (رایگان در سهمیهٔ عمومی)
- درسهای باندلشدهٔ داخل APK (۲٬۸۷۶ جمله) فعلاً موتور دستگاهاند؛ پوشش آنها نیازمند ایندکس صدای جداست

## مقایسه با مسیر APIای قبلی

`scripts/content/ttsProvider.mjs` (OpenAI/Google/ElevenLabs) همچنان هست، ولی **دیگر پیشفرض نیست**؛
برای تیمهایی که به آن سرویسها دسترسی دارند گزینهای اختیاری است. مسیر پیشنهادی برای ایران،
`tts-offline.yml` است.

## محدودیت صادقانه

- eSpeak صدایی رباتی دارد؛ مزیتش یکسانی، آفلاین بودن و حذف وابستگی به موتور گوشی است، **نه** زیبایی صدا.
  برای کیفیت طبیعی، `engine=auto` مدلهای عمومی Piper را امتحان میکند (بدون توکن) و در صورت شکست
  به eSpeak برمیگردد؛ آدرس مدلها با ورودی `voice_map` قابل اصلاح است.
- تولید صدا کیفیت تلفظ را تضمین میکند، نه درستی جملات را؛ بازبینی `docs/native-review.md` پابرجاست.
- تا وقتی رندر اجرا نشود اپ دقیقاً مثل امروز کار میکند (موتور دستگاه) — پس اضافهشدن این زیرساخت
  ریسکی برای نسخهٔ فعلی ندارد.
