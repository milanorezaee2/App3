# اعلان زندهٔ چت اندروید بدون Firebase/FCM

## خلاصهٔ تغییر

در اندروید، مسیر اعلانِ پس‌زمینه از کار دوره‌ای Expo با حداقل بازهٔ ۱۵ دقیقه‌ای به یک ماژول بومی Kotlin تغییر کرده است. پس از روشن‌کردن گزینهٔ «اعلان پیام‌های تازه»، سرویس foreground اندروید یک اتصال WebSocket به Supabase Realtime نگه می‌دارد و برای پیام‌های تازه، درخواست چت پشتیبانی و تغییر وضعیت درخواست، اعلان محلی می‌سازد. این مسیر از FCM، فایل `google-services.json` و توکن Expo برای اندروید استفاده نمی‌کند.

وقتی برنامه باز است، مسیر Realtime موجود در JavaScript مسئول بنر داخل برنامه است و سرویس بومی اعلان تکراری سیستم‌عامل نمی‌سازد. متن پیام در اعلان نمایش داده نمی‌شود. نشست و refresh token سرویس با AES-GCM و کلید Android Keystore نگهداری می‌شود؛ هنگام خروج از حساب، سرویس متناظر متوقف می‌شود.

## بررسی تنظیمات Expo و EAS

- `app.json` از افزونهٔ `expo-notifications`، کانال `milo-chat` و تصویر تک‌رنگ اختصاصی `assets/images/notification-icon.png` استفاده می‌کند. این آیکن ۹۶×۹۶، سفید با پس‌زمینهٔ شفاف است.
- `app.config.js` فایل‌های Google Services را فقط در صورت وجود به buildهای قدیمی Expo Push/FCM متصل می‌کند؛ مسیر جدید اندروید به آن فایل‌ها نیاز ندارد. شناسهٔ EAS از `app.json` حفظ می‌شود، حتی اگر متغیر `EAS_PROJECT_ID` در CI تنظیم نشده باشد.
- پروفایل‌های `eas.json` از قبل برای APK داخلی پیکربندی شده‌اند؛ برای این پیاده‌سازی تغییر دیگری در آن فایل لازم نبود. برای استفاده از ماژول Kotlin باید APK جدید ساخته و نصب شود؛ Expo Go یا APK قدیمی این ماژول را ندارد.
- مسیر Android از Firebase استفاده نمی‌کند؛ مسیر قبلی Expo Push برای iOS دست‌نخورده مانده است.

## ساخت و آزمایش

پس از همگام‌سازی شاخه با محیط build و ورود به EAS، یکی از پروفایل‌های زیر را اجرا کنید:

```bash
eas build --platform android --profile learner
eas build --platform android --profile admin
```

پس از نصب APK جدید:

1. اجازهٔ اعلان‌های Android را فعال کنید.
2. در صفحهٔ گفت‌وگو گزینهٔ اعلان پیام را روشن کنید؛ اعلان دائمی «اعلان پیام‌های Milo» باید ظاهر شود.
3. وضعیت سرویس باید از «در حال اتصال» به «متصل» برسد.
4. دکمهٔ «آزمایش اعلان روی همین گوشی» را بزنید. handler اعلان برای رویداد `local-test:` عمداً در foreground نیز بنر را نمایش می‌دهد.
5. اپ را به پس‌زمینه ببرید و از دستگاه دیگر پیام بفرستید. اعلان، متن خصوصی پیام را نمایش نمی‌دهد و با لمس آن گفت‌وگو باز می‌شود.

اگر اعلان آزمایشی ثبت شود ولی روی گوشی نمایش داده نشود، مجوز اعلان، کانال «پیام‌ها و درخواست‌های چت»، تنظیمات نمایش روی صفحهٔ قفل و محدودیت‌های باتری سازندهٔ گوشی را بررسی کنید.

## پیش‌نیاز Supabase

مهاجرت‌های فعلی مخزن، جدول `public.messages` و جدول `public.support_requests` را به publication به نام `supabase_realtime` اضافه می‌کنند. دسترسی واقعی همچنان به JWT کاربر، RLS، عضویت گفت‌وگو و فعال‌بودن Realtime در پروژه بستگی دارد. اگر build روی «در حال اتصال مجدد» می‌ماند، ابتدا URL و کلید عمومی Supabase، دسترسی WebSocket شبکه و سیاست‌های RLS پروژه را بررسی کنید.

جدول `chat_push_tokens` برای این مسیر اندروید استفاده نمی‌شود؛ در نسخهٔ فعلی همچنان می‌تواند برای توکن‌های iOS و مسیر Expo Push کاربرد داشته باشد. بنابراین نبودن توکن جدید اندروید در آن جدول به‌تنهایی خطا محسوب نمی‌شود.

## محدودیت‌های مهم

این روش جایگزین کاملاً هم‌ارز FCM نیست. اتصال زنده تا وقتی سرویس foreground، شبکه و سیاست‌های دستگاه اجازه بدهند نزدیک به بلادرنگ است؛ Doze، صرفه‌جویی شدید باتری، محدودیت‌های اختصاصی سازنده، قطع اینترنت، توقف اجباری اپ یا لغو مجوز می‌تواند آن را قطع یا با تأخیر مواجه کند. پس از راه‌اندازی مجدد گوشی، برنامه را یک‌بار باز کنید تا سرویس opt-in دوباره برقرار شود. اعلان دائمیِ سرویس برای شفافیت و اولویت اجرایی Android نمایش داده می‌شود.

Manifest از نوع `specialUse` همراه توضیح subtype استفاده می‌کند. اگر اپ قرار است از Google Play توزیع شود، نوع سرویس foreground و کاربرد آن باید در فرم/فرایند بررسی Play نیز اعلام و تأیید شود؛ پذیرفته‌شدن این مورد تضمین‌شده نیست. برای توزیع مستقیم APK داخلی، build جدید EAS کافی است.

## نتیجهٔ بررسی محلی

`npm run typecheck`، هر دو بررسی استاتیک اعلان، حل تنظیمات `npx expo config --json` و `npx expo prebuild --platform android --no-install` موفق شدند. ابزار Android SDK در محیط بررسی حاضر نبود، بنابراین Gradle APK واقعی از این محیط ساخته نشد. هیچ commit یا push به GitHub انجام نشده است.
