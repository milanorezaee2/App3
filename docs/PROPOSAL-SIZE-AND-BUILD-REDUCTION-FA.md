# پیشنهاد فنی: کاهش حجم مخزن و APK + جلوگیری از بازگشت

**وضعیت:** پیش‌نویس برای بررسی (RFC)
**تاریخ:** ۶ نوامبر ۲۰۲۶
**دامنه:** مخزن App3 — پاکسازی، هرس وابستگی، پیکربندی ساخت، گاردهای CI
**اصل حاکم:** هیچ تغییر رفتاری در اپ مجاز نیست. هر مرحله مستقل قابل بازگشت است.

## ۰. خلاصهٔ مدیریتی

سه عدد اندازه‌گیری‌شده و یک عدد تخمینی داریم:

| سنجه | امروز | هدف پیشنهادی |
|---|---:|---:|
| حجم مخزن (بدون `.git`) | ۱۶.۹ MB | ~۹ MB |
| حجم APK یونیورسال | ~۱۰۰ MB | ~۳۰ MB |
| APK تک‌معماری (arm64) | ~۳۵–۴۵ MB | ~۲۲–۲۵ MB |
| باندل JS | ~۶–۱۰ MB | ~۴ MB |

نکتهٔ کلیدی که باید صریح گفته شود: **پاکسازی مخزن، APK را کوچک نمی‌کند.** این دو مسئلهٔ جدا هستند و باید جدا مدیریت شوند. پیشنهاد زیر آن‌ها را به‌صورت دو مسیر موازی می‌بیند و در انتها با گاردهای CI قفل می‌کند تا دوباره برنگردند.

## ۱. اهداف و معیارهای پذیرش

پیشنهاد وقتی «موفق» است که همهٔ این‌ها برقرار باشند:

1. `npm run typecheck` بدون خطا.
2. تمام `validate:*`های موجود سبز.
3. `npx expo export --platform web` موفق.
4. APK ساخته‌شده روی دستگاه واقعی باز شود و **صفحهٔ اول، انتخاب زبان، یک درس انگلیسی، یک درس روسی، ورود، و اعلان چت** کار کند.
5. حجم APK ≤ ۳۵ MB (یونیورسال ≤ ۴۵ MB).
6. هیچ دارایی بالای ۲۰۰ KB بدون ارجاع در مخزن نماند — و این با CI تضمین شود.

### ⚠️ تضاد دوم — `react-native-reanimated`

این پکیج در کد **هیچ importی ندارد**، اما:

- `package.json` آن را دارد و `babel.config.js` پلاگینش را فعال می‌کند.
- `mocks/react-native-reanimated.js` می‌گوید «برای کم کردن حجم نیتیو حذف شد».
- **`scripts/verify-chat-notifications.mjs:24` به‌صراحت assert می‌کند که این پکیج نصب باشد و پلاگین Babel وصل باشد.**

یعنی این یک تصمیم عمدی است، نه فراموشی — و توضیح داخل `mocks/` کهنه است. Reanimated در `react-native-keyboard-controller` نقش دارد. **پیشنهاد من: در این مرحله دست نزنید.** فقط پس از آزمون دستی روی دستگاه و با تغییر هم‌زمان آن assert تصمیم بگیرید. این تنها موردی است که در آن «حذف» را توصیه نمی‌کنم.

## ۵. کارگاه C — پیکربندی ساخت (ریسک: پایین، اثر: بزرگ‌ترین — ۱۰۰ → ~۳۰ MB)

اینجا ۷۰٪ مشکل APK حل می‌شود.

### C1. از APK یونیورسال به AAB

```json
"android": { "buildType": "app-bundle" }
```

فروشگاه و توزیع‌کننده فقط معماری دستگاه کاربر را تحویل می‌دهد. این **بزرگ‌ترین تک‌اقدام** است.

اگر عمداً APK مستقیم (خارج از فروشگاه) پخش می‌کنید، APK را **تک‌معماری** بسازید — یک نسخه برای `arm64-v8a` و در صورت نیاز یکی برای `armeabi-v7a`:

```gradle
// android/app/build.gradle (پس از prebuild)
android {
  splits { abi { enable true; reset(); include 'arm64-v8a'; universalApk false } }
}
```

### C2. روشن‌کردن R8 و حذف منابع

```json
[
  "expo-build-properties",
  {
    "android": {
      "enableProguardInReleaseBuilds": true,
      "enableShrinkResourcesInReleaseBuilds": true,
      "extraProguardRules": "path/to/proguard-rules.pro"
    }
  }
]
```

مزیت: این تنظیم در `app.json` می‌نشیند و در `expo prebuild` بازتولید می‌شود — پس پایدار است و با هر بیلد از دست نمی‌رود.

### C3. پاک‌کردن `packagingOptions`

در `app.json` این خط هست:

```json
"pickFirst": ["**/libc++_shared.so", "**/libjsc.so", "**/libfbjni.so"]
```

`pickFirst` یعنی «تکراری‌ها را نادیده بگیر». وجودش نشان می‌دهد چیزی موتور باینری را دو بار وارد می‌کند. بعد از حذف وابستگی‌های B، این را بردارید و ببینید بیلد می‌شکند یا نه. اگر شکست، ریشه را درآورید نه علامت را.

### C4. سنجش قبل از هر تغییر

پیشنهاد می‌کنم اول **نقشهٔ دقیق داخل APK** را بگیرید تا دیگر حدس نزنیم. این را در CI هم بگذارید:

```bash
unzip -l MiloMultilang.apk \
  | awk 'NR>3 { s[$4]+=$1 } END {
      for (p in s) {
        split(p, a, "/")
        key = (a[1]=="lib") ? "lib/" a[2] : a[1]
        t[key]+=s[p]
      }
      for (k in t) printf "%10.1f MB  %s\n", t[k]/1048576, k
    }' | sort -rn
```

خروجی مستقیم می‌گوید چند مگابایت در `lib/arm64-v8a`، چند در `classes.dex`، چند در `assets/`. **این تنها راه حرفه‌ای تصمیم‌گیری است.** پیشنهاد: این خروجی را در هر بیلد به‌عنوان artifact ذخیره کنید.

## ۶. کارگاه D — اسکوپ زبان در باندل (ریسک: متوسط، اثر: ۲–۴ MB)

`lib/languages/catalog.ts` هر سه زبان را استاتیک import می‌کند، در حالی که `eas.json` برای هر نسخه اسکوپ تعریف کرده (`en,ru` / `en,tr`). نتیجه: نسخهٔ learner حامل ۱.۶ MB محتوای ترکی است.

پیشنهاد: تبدیل `catalog` به بارگذاری تنبل و جدا کردن `lessonsCount` به یک فایل عددی سبک:

```ts
// lib/languages/catalog.ts — بدون import محتوا
const lessonsCount = { en: 508, ru: 240, tr: 460 }; // اعداد از build manifest
```

و `app/learn/[language]/*` محتوا را با `require()` شرطی داخل `if (LANGUAGE_SCOPE.includes(lang))` بارگذاری کند.

**چرا این را به آخر گذاشتم:** این تنها کاری است که به کد منطق اپ دست می‌زند. باید بعد از پاک‌سازی‌ها انجام شود تا اگر چیزی شکست، علتش روشن باشد.

## ۸. کارگاه F — گاردهای جلوگیری از بازگشت (مهم‌ترین بخش این پیشنهاد)

مشکل واقعی این نبود که یک فایل ۳.۵ مگابایتی در مخزن بود؛ این بود که **هیچ‌چیز مانع ورودش نشد و هیچ‌چیز آن را نگرفت.** بدون این کارگاه، شش ماه بعد همین وضع برمی‌گردد.

### F1. `scripts/verify-repo-hygiene.mjs` (جدید)

در CI اجرا شود و در این موارد fail کند:

1. هر فایل غیرکد بالای **۲۰۰ KB** که در هیچ سورسی ارجاع ندارد.
2. وجود پوشه‌های `transfer/`، `*.zip` یا `*dist*` در ریشه.
3. هر پکیج در `package.json` که در هیچ فایلی import نشده (با فهرست استثنای مستند: `react-dom`، `react-native-web`، `typescript`، `@types/react`، `@babel/core`، `react-native-screens`، `react-native-gesture-handler`).
4. تصویری با پسوند و امضای فایل ناهم‌خوان (همان اشتباه PNG با نام `.jpg`).

### F2. بودجهٔ حجم (Size Budget) در CI

یک فایل `docs/BUILD-BUDGET.md` با اعداد مصوب، و در workflow:

```bash
SIZE=$(stat -c%s MiloMultilang.apk)
LIMIT=$((45 * 1024 * 1024))
[ "$SIZE" -le "$LIMIT" ] || { echo "APK over budget: $SIZE"; exit 1; }
```

اثر روانی این خط از هر بازبینی کدی بیشتر است.

### F3. گزارش ترکیب APK به‌عنوان artifact

اسکریپت بخش C4 در هر بیلد اجرا و خروجی آپلود شود. اگر کسی وابستگی سنگینی اضافه کرد، در دیف همان PR دیده می‌شود.

### F4. قاعدهٔ بررسی کد

در `README-FA.md` یک خط اضافه شود: «هیچ فایل باینری بالای ۲۰۰ KB بدون تأیید صریح و بهینه‌سازی وارد مخزن نمی‌شود.» تصاویر باید حداکثر عرض ۱۶۰۰ پیکسل و JPEG کیفیت ۸۲ باشند.
